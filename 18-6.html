一、智能客服系统流程图 flowchart TD

flowchart TD
    A([用户发起咨询]) --> B[智能客服机器人]
    B --> C[意图识别 NLU
分词 · 实体抽取 · 相似度匹配]
    C --> D{命中知识库?}
    D -- 是 --> E[返回标准答案]
    E --> F{用户是否满意?}
    D -- 否 --> H[转人工客服]
    F -- 是 --> G([会话结束
记录满意度评价])
    F -- 否 --> H
    H --> I[人工解决问题]
    I --> J[生成工单]
    J --> K[答案沉淀入知识库]
    K -. 反馈学习 · 优化模型 .-> C

虚线为「反馈学习」闭环：人工解决的新问题会沉淀进知识库，让机器人下次能直接命中。

二、智能客服数据库 ER 图 erDiagram

erDiagram
    USER ||--o{ SESSION : "发起"
    SESSION ||--o{ MESSAGE : "包含"
    MESSAGE }o--o| KNOWLEDGE : "命中"
    AGENT ||--o{ TICKET : "处理"
    USER ||--o{ TICKET : "提交"
    SESSION ||--o| TICKET : "升级为"
    KNOWLEDGE }o--|| CATEGORY : "属于"

    USER {
        int zxc_user_id PK "用户编号"
        string zxc_name "昵称"
        string zxc_phone "手机号"
        datetime zxc_create_time "注册时间"
    }
    SESSION {
        int zxc_session_id PK "会话编号"
        int zxc_user_id FK "所属用户"
        string zxc_channel "渠道(App或网页)"
        datetime zxc_start_time "开始时间"
    }
    MESSAGE {
        int zxc_msg_id PK "消息编号"
        int zxc_session_id FK "所属会话"
        string zxc_role "角色(用户或机器人)"
        text zxc_content "消息内容"
        int zxc_knowledge_id FK "命中的知识条目"
    }
    KNOWLEDGE {
        int zxc_knowledge_id PK "知识条目编号"
        string zxc_question "标准问题"
        text zxc_answer "标准答案"
        float zxc_similarity "命中阈值"
        int zxc_category_id FK "所属分类"
    }
    CATEGORY {
        int zxc_category_id PK "分类编号"
        string zxc_name "分类名称"
    }
    AGENT {
        int zxc_agent_id PK "客服编号"
        string zxc_name "客服姓名"
        string zxc_group "所属技能组"
    }
    TICKET {
        int zxc_ticket_id PK "工单编号"
        int zxc_session_id FK "来源会话"
        int zxc_user_id FK "提交用户"
        int zxc_agent_id FK "处理客服"
        string zxc_status "状态(处理中或已关闭)"
        text zxc_result "处理结果"
    }

核心关系：一个用户可发起多个会话，每个会话包含多条消息；消息命中知识条目即机器人作答，未命中则升级为工单由人工处理。
